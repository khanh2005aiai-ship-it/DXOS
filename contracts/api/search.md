# Global organization search — DXOS-FEATURE-EXPANSION-001

Contract recorded before implementation. Additive GET `/api/v1/organizations/:organizationId/search`; no schema, migration, external search engine, dependency or new permission.

JWT plus ACTIVE user/session/organization/membership required. Resolve effective grants inside a serializable read transaction. Each category uses the existing read permission: employees → employee:read, tasks → task:read, documents → file:read, departments → department:read. Notifications need active membership and always filter recipientUserId to the authenticated actor. No administrator-name bypass, automatic grant, client-provided grants or cross-tenant results. File results include AVAILABLE metadata only.

Strict query: `q` trimmed 2–100 characters, no control characters; `type` optional enum all (default), employees, tasks, documents, departments, notifications; `limit` integer 1–25/default5 **per category**; `after` optional UUID only when type is one category. Unexpected query keys are 400. SQL uses parameterized Prisma queries with literal escaping of LIKE wildcard characters. Query text and result contents are never included in audit/log metadata.

Response `{groups:{employees, tasks, documents, departments, notifications}}`. Unrequested or unauthorized categories are null. A permitted category is `{items:[{id,title,subtitle}],nextCursor}` where subtitle is nullable safe code/type only: employeeCode, null for Task, contentType for Document, department code, null for Notification. Search uses employee displayName/code, task title, document originalFilename, department name/code and notification title. No bodies, personal email/phone, employee user IDs, storage keys, tokens, session data, permission lists or audit metadata. At most 125 items for type=all. Single-category paging uses ID ascending keyset bounds, consistent with entity lists; after is an opaque ordering bound without a foreign-resource lookup. A foreign UUID cannot change organization/recipient/permission scope or reveal its existence. No total-count scans and no relevance scoring in V1.

401 invalid/missing authentication; 403 inactive/missing organization membership or explicit single category without its permission; malformed or missing organization identifiers also get generic 403 through authorization. Authorized no matches → 200 empty items, not 404. No resource detail/foreign identifier oracle. Successful reads create no audit event; organization/category access denials use the existing redacted authorization-denied event.

Frontend Ctrl+K/Cmd+K opens an accessible dialog. Search waits 250ms and requires two characters; users can choose a category and load further pages. Changing query/category/org clears results and ignores stale responses. Vietnamese loading, empty, denied and retry states. Task results open Task Detail; other results open their existing module. Search does not invent unsupported detail routes or send document bytes/organization data to AI.

Limit: literal substring matching under the configured MySQL collation may scan tenant rows; bounded output does not imply indexed full-text search. Measure latency and query plans before adding a separate index/service. No search of attachment contents or notification bodies.
